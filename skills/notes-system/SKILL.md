# Scaffold the shift-log notes system into a project

You are installing a **portable shift-log tracker**. The anti-pattern it fixes: every session dumps
a dated prose blob into one always-read context file and a clock rule evicts the oldest — so that
file bloats with history the next agent doesn't need, and good notes die by age not relevance. You
replace it with one note per handoff, filed by durable category, with a GENERATED router and a
SEMANTIC keep/archive test. Then you hand back a one-line summary.

## The model (what you're installing)
- **One note per handoff**, a plain `.md` under `.ai/notes/<category>/YYYY-MM-DD-<slug>.md`, with a
  small structured header (`Status` / `Category` / `Date` / `So-what`, optional `Job`/`Supersedes`).
- **One GENERATED view** — `NOTES_INDEX_GENERATED.md`, the router — never hand-edited.
- **A guard hook** (PreToolUse) that DENIES edits to the generated router so it can't drift.
- **A context-file refresh** — `--render` rewrites a `<!-- RECENT NOTES -->` marked block.
- **Keep/archive is SEMANTIC**: `live` while it steers the next agent; `settled` → `_archive/`
  verbatim when its arc is closed. No cap, no FIFO, no clock.
- **The agent's only recurring action**: write a note via the `notes` skill, then `--render`.

## Steps (in order; each is idempotent)

1. **Locate the bundle.** This skill ships beside the portable bundle:
   `tool/notes_tool.py`, `hook/guard_notes_generated.py`, `templates/{README,AGENTS,NOTE_TEMPLATE}.md`,
   `usage-skill/SKILL.md` (the `notes` usage skill). Confirm those exist before copying.

2. **Confirm the target + choose paths.** Decide where the tool lives in the target
   (default `scripts/notes/notes_tool.py`) and the notes dir (default `.ai/notes`). Verify the
   target has a Python 3 on PATH (stdlib only — no pyyaml/pandas needed).

3. **Copy the tool + hook.**
   - Copy `tool/notes_tool.py` → `<target>/scripts/notes/notes_tool.py`.
   - Copy `hook/guard_notes_generated.py` → `<target>/.claude/hooks/guard_notes_generated.py`.

4. **Scaffold the store.** From the target root run `python scripts/notes/notes_tool.py --init`.
   This creates the category folders + `_archive/`, writes `notes.config.json` (if absent) and the
   `README.md` / `AGENTS.md` / `NOTE_TEMPLATE.md` (copied from the bundle templates if absent), and
   renders an empty router. It is idempotent — safe to re-run.

5. **Tune the taxonomy (owner-facing).** Open `.ai/notes/notes.config.json`. The default categories
   are generic (`process` / `ops` / `decision` / `mechanism` / `work`). Adjust `categories` (names +
   keywords) and `context_file` to the target project's real vocabulary. FIRST match wins; keep the
   default fallthrough LAST. Changing the taxonomy is an owner decision — ask if unsure.

6. **Install the usage skill.** Copy `usage-skill/SKILL.md` → `<target>/.claude/skills/notes/SKILL.md` so agents in
   the target can write notes correctly.

7. **Wire the PreToolUse guard hook** in the target's `.claude/settings.json` (merge, don't clobber
   an existing hook block):
   ```json
   { "hooks": { "PreToolUse": [ { "matcher": "Edit|Write|MultiEdit",
     "hooks": [ { "type": "command",
       "command": "python \"$CLAUDE_PROJECT_DIR/.claude/hooks/guard_notes_generated.py\"" } ] } ] } }
   ```
   On Windows use the same POSIX-style `$CLAUDE_PROJECT_DIR` form — the harness expands it.

8. **Wire the commands.** If the target is a Node project, add to `package.json` scripts (point at
   the project's Python — e.g. `.venv\\Scripts\\python.exe` on Windows, else `python`):
   `notes:render`, `notes:selftest`, `notes:new` (= `<python> scripts/notes/notes_tool.py --<cmd>`).
   If not a Node project, tell the owner the raw `python scripts/notes/notes_tool.py --<cmd>` calls.

9. **Wire the context-file pointer.** Ensure the target's always-read context file contains the
   marked block so `--render` can refresh it:
   ```
   <!-- RECENT NOTES: generated by notes_tool.py --render, do not hand-edit -->
   <!-- END RECENT NOTES -->
   ```
   Add one pointer line in the project's root `CLAUDE.md`/`AGENTS.md` session-end section telling
   agents to write handoffs via the `notes` skill (not into the context file).

10. **(Optional) seed from existing history.** If the target already has a prose shift log, the port
    is manual: split it into per-note files under the right categories (the old tokens-ingest tool
    had a bespoke `--port`; this generic tool does not, because source formats vary). Do it by hand
    or with a throwaway script, mark ported notes `Status: settled`, then `--render`.

11. **Verify + report.** Run `python scripts/notes/notes_tool.py --selftest` (must be GREEN) then
    `--render`. Report: notes dir path, category list, N notes tracked, hook wired yes/no, commands
    wired yes/no. Do NOT claim done if `--selftest` is not GREEN.

## Non-negotiables (carry these into the target)
- **Keep/archive is SEMANTIC, never by clock.** No cap, no FIFO, no age trigger.
- **A note body never holds a number+CI** — it points at the durable result.
- **Never hand-edit the generated router** — the hook denies it; `--render` owns it.
- **Categories are few on purpose.** Adding one is an owner decision, like an ADR.
